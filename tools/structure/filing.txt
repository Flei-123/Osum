# tools/structure/filing.txt -- WO EINE DATEI LIEGEN SOLL.
#
# Je Zeile: `verzeichnis modul`. Das Verzeichnis ist relativ zu
# `kernel/`; `.` heisst "bleibt oben liegen".
#
# UNTERSCHIED ZU schichten.txt: dort steht, wen ein Modul rufen DARF
# (die Aufrufrichtung). Hier steht, wo es LIEGT (die Ablage). Beides
# faellt meist zusammen, aber nicht immer -- `dev` zerfaellt raeumlich
# in `drv/blk`, `drv/net`, `drv/usb`, `drv/hid`, `drv/snd` und
# `drv/con`, weil "26 Treiber in einem Ordner" genauso unuebersichtlich
# waere wie 129 Dateien in `kernel/`.
#
# `tools/struktur/run.sh` prueft BEIDES: die Aufrufrichtung gegen
# schichten.txt und die tatsaechliche Ablage gegen diese Datei.
#
# ------------------------------------------------------------ DIE ABLAGE
#
#   lib/      reine Hilfen ohne Abhaengigkeit nach unten
#   arch/     schon da: x86_64/, aarch64/ -- dazu die prozessornahen
#             Dateien, die bisher flach lagen
#   mm/       Speicher
#   sched/    Faeden, Prozesse, Zeit, Signale
#   sync/     Sperren und Atomik
#   ipc/      was Prozesse miteinander tun: Rechte, Griffe, Auftraege
#   ldr/      Lader: ELF, Module, Startmodule
#   crypto/   Krypto (schon angelegt)
#   acpi/     ACPI und AML
#   bus/      Busse und Entdeckung (schon angelegt)
#   pwr/      Energie: Akku, Abschalten, Messung
#   block/    Blockschicht ueber den Plattentreibern
#   fs/       Dateisysteme und Namensraum
#   net/      der Netzweg
#   usb/      der USB-Kern
#   drv/blk   Plattentreiber
#   drv/net   Netzkartentreiber
#   drv/usb   USB-Hostadapter
#   drv/hid   Eingabegeraete
#   drv/snd   Ton
#   drv/con   Konsole und Terminal
#   drv/gpu   Anzeigetreiber
#   gfx/      Rahmenpuffer, Schrift, Anzeigemodus
#   ui/       Fenster, Kacheln, Zeiger
#   sys/      die Systemaufruftafel
#   diag/     Diagnose (schon angelegt)
#   boot/     der Start
#
# `.` = bleibt in kernel/ liegen. Die Begruendung je Datei steht in
# docs/STRUKTUR.md, Abschnitt "Was liegen bleibt".
