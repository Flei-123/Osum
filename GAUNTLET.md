# Gauntlet-Log — os-wmplug
**Ziel:** Baue im BESTEHENDEN Repo-Worktree /root/os-wmplug (Zweig `wmplugin`, OrientOS/Osum, Sprache Firn, .fi-Dateien) ein ERWEITERUNGSSYSTEM FUER DEN FENSTERSERVER — Vorbild Hyprland-Plugins/hyprpm, aber ohne deren Grundfehler.

DER PUNKT DER RUNDE: Hyprland laedt Plugins als .so DIREKT IN DEN COMPOSITOR-PROZESS und hookt Funktionen. Bei uns waere das Fremdcode in Ring 0, denn unser Fensterserver laeuft IM KERNEL (kernel/wm.fi, 9265 Zeilen). Die Hausregel /root/osum-roadmap/FREMDSOFTWARE.md Regel 4 lautet woertlich "Kein Fremdcode im Kern". Also: PLUGINS LAUFEN IN RING 3 und wirken ueber eine schmale, versionierte Schnittstelle am Fensterserver mit. Ein abstuerzendes Plugin darf das System NIEMALS mitnehmen.

=== GEPRUEFTE FAKTEN (schon nachgesehen, nicht neu suchen) ===
- Syscall-Weg: kernel/sys.fi Zeile ~9950 `if number >= WM_BASE { return gfx.sys_wm(state, me, number, a0..a4) }` -> kernel/gfx.fi:377 `sys_wm` reicht durch an -> kernel/sysgui.fi:581 `fn wm_call(state, me, number, a0..a4)`. DORT gehoeren die neuen Aufrufe hin, nach dem Muster der vorhandenen.
- WM_BASE=2100, hoechster belegter Aufruf WM_APP=2116, `const WM_MAXNR: u64 = 2116`. Neue Aufrufe ab 2117, WM_MAXNR mit hochziehen. ACHTUNG: `wm_call` prueft ganz oben `if number > sys.WM_MAXNR { return cap.err(cap.E_INVALID) }`.
- Fenstertafel in kernel/wm.fi: Felder W_USED 0x00, W_ID 0x08, W_OWNER 0x10, W_X 0x18, W_Y 0x20, W_W 0x28, W_H 0x30, W_LAYER 0xE0, W_FLAGS 0xE8, W_TITLE 0xC0, W_APP 0x118, W_NODE 0x100. Zugriff ueber wg()/wsv(), Skalare ueber gs()/ss(). Ereignisring: EV_OFF=0x2000 in kstate.DSK_OFF, EV_SLOTS=32, EV_BYTES=16, `fn ev_push(state, i, typ, a, b, c)` (~Zeile 6618) — dort entstehen die Ereignisse, die ein Plugin abonnieren soll.
- Ebenen: L_DESK=0, L_NORMAL=1, L_TOP=2 (Taskleiste), L_FULL=3, L_MENUE=4, L_POPUP=5, L_TIP=6.
- Rechtemuster fuer Zugriff auf FREMDE Fenster: `is_taskbar(state, me)` in sysgui.fi (verlangt eigenes Fenster auf L_TOP). Genau dieses Muster fuer Plugin-Rechte weiterdenken.
- Handles/Rechte: kernel/cap.fi, cap.R_READ/R_WRITE/R_MANAGE/R_INSPECT, Fehler cap.err(cap.E_RIGHTS|E_INVALID|E_NOTFOUND|E_EXHAUSTED).
- Speicher: kstate.fi, KDATA_SIZE=0x100000, DSK_OFF=0x64000 (DSK_MAX 0x4000). Fuer die Plugintafel eine FREIE Seite nehmen und mit `python3 tools/kernel/memmap.py` pruefen (meldet Kollisionen; aktuell 110 Bereiche, 0 Kollisionen). Die neue Konstante gehoert nach kstate.fi zu den anderen *_OFF.
- Modusbits/Bootwoerter: kstate.fi M_*, hoechstes belegt M_VGPUEREIG=985 (Wort 15, Bit 25) -> neue ab Bit 26. Erkannt werden sie in kernel/kmain.fi mit `find_word(cmd, ...)` + `kstate.mode_add(state, kstate.M_...)` (Muster dort abschauen, z. B. bei `wm`, `k13run`, `handle`). WARNUNG aus dem Repo: kurze Woerter treffen Teilwoerter — eindeutige Namen waehlen.
- Zeit: time.fi TICK_HZ=100, kstate.TICKS (Marken), time.tsc() fuer feine Messung. Signale: kernel/signal.fi, SIGSEGV=11, SIGKILL=9, `signal.send_pid(...)`, `sched.find_pid(state,pid)`, `sched.tget/tset`.
- Kachelbaum: kernel/tile.fi (kennt nur Rechtecke + eine client-Zahl je Blatt, KEINE Fenster). Syscalls SYS_OSUM_TILEGET=1820, TILEDO=1821, TILECONF=1822, TILEBIND=1823, bedient in sysgui.fi `tile_call`. Ring-3-Bedienprogramm kernel/user/tiling.fi ist die BESTE VORLAGE fuer /bin/wmplug (Aufbau, Ton, Argumentparsen, `import ulib`, `export { u_start }`).
- KEINE REKURSION im Kernel: Kernstapel ist 16 KiB und war schon einmal fast voll. Schleifen statt Rekursion.

**Messlatte:** ABNAHME NUR MIT ECHTEN MESSUNGEN AUS EINEM WIRKLICH GEBOOTETEN KERNEL. Behauptungen ohne Beleg zaehlen null.

1. RING-3-TRENNUNG (Kern der Runde): Plugins sind Ring-3-Prozesse. NIRGENDWO wird Fremdcode in den Kernel geladen/gelinkt/gesprungen. Der Kernel WARTET NIE auf ein Plugin (kein blockierender Aufruf im compose-/poll-Pfad). Wer das verletzt, hat die Runde verfehlt, egal wie huebsch der Rest ist.
2. SCHNITTSTELLE: versionierte, schmale ABI ueber neue WM-Syscalls ab 2117 (WM_MAXNR in kernel/sys.fi muss mitwachsen; Aufrufe in kernel/sysgui.fi wm_call). Plugin abonniert Ereignisse (Fenster auf/zu/Fokus, Arbeitsflaeche, Kachelbaum, Tastenkuerzel) und loest Aktionen ueber VORHANDENE WM-Syscalls aus. KEIN neuer Zeichenweg am fUi vorbei.
3. HARTE GRENZEN, JEDE EINZELN GEMESSEN UND IM SERIENPROTOKOLL BELEGT:
   a) Absturz-Gegenprobe: Plugin macht absichtlich SIGSEGV -> Schreibtisch laeuft NACHWEISLICH weiter (Foto danach + weitere compose-Runden), Plugin abgemeldet, Grund steht auf der seriellen Leitung.
   b) Haenger-Gegenprobe: Plugin in Endlosschleife -> Zeitlimit greift, Plugin abgemeldet, Schreibtisch laeuft weiter. Der Kernel darf dabei KEINE Bildrate verlieren.
   c) Rechte-Gegenprobe: Plugin ohne Recht auf eine Aktion bekommt einen FEHLERCODE zurueck UND die Aktion ist nachweislich NICHT passiert (am Zustand gemessen, nicht am Rueckgabewert allein).
4. AN/AUS ZUR LAUFZEIT: Plugin ein- und ausschalten OHNE Neustart des Fensterservers. ZWEI Fotos (docs/shots/wmplug/), die sich SICHTBAR unterscheiden, maschinell nachgerechnet (Farbe an einer Koordinate, wie tools/gfx/checkshot.py es macht) — nicht nur "sieht anders aus".
