# A11Y — the accessibility tree, its rights and its bus

**Status: 30.09.2026, round A11Y-2** (roadmap S-007, S-008, AB-021). This
is the port of the branch `archiv/a11y` (28.08.2026, commits
983eeedc..4b0f10f3) onto today's main, plus what that branch listed as
open: the right falls at exec, controls can be *pressed* through the
tree, and reading and pressing go through the action bus.

Test: `bash tools/a11y/run.sh` (section 8). Photos: `docs/shots/a11y/`.

---

## 1. The decision, and why now

An accessibility tree describes the screen in terms instead of pixels:
*here is a button, it is called "Save", it is enabled, it has the focus,
it lies at (12, 156), 100 × 28*. Without it a screen reader can only scan
a picture — and a picture does not say what a button is.

**Why in the protocol and not later:** afterwards every single program has
to be touched again; now it costs one place.

| System | Protocol | Tree came | Result |
|---|---|---|---|
| X11 | 1987 | AT-SPI, 2003 | every toolkit family retrofitted it on its own |
| Windows | 1985 | MSAA 1997, UIA 2005 | two layers on top of each other |
| Wayland | 2008 | still beside it, over D-Bus | a window protocol without a tree |
| macOS | NeXTSTEP | in the responder tree from the start | apps are accessible *without their authors thinking of it* |

In Osum this is cheap: the window server is in the kernel
(`kernel/ui/wm.fi`) and every program uses the same widget layer
(`kernel/user/wlib.fi`). The tree is made **once**, in `wlib.ax_tick` /
`wlib.ax_flush`, after each picture. `kernel/user/a11ydemo.fi` puts nine
controls on the screen and does three things for its accessibility: it
names its password field (`ax_name`) and says which bus action two
buttons stand for (`ax_action`). Everything else comes from wlib.

## 2. What a node carries

96 octets. The packing is in `kernel/ui/ax.fi` (kernel), `kernel/user/wlib.fi`
(builder), `kernel/user/wlibc.fi` (calls) and `kernel/user/axd.fi` (reader);
`tools/a11y/fields.py` holds all four against each other.

```
  +0   role | state << 8 | win << 16 | parent << 24
       | task << 32 (set by the KERNEL) | slot << 40 (set by the KERNEL)
       | widget << 48
  +8   x | y << 16 | width << 32 | height << 48      (window-relative)
  +16  value (for a window node: the window-server id, checked)
  +24  accessible name, 40 octets
  +64  bus action this control stands for, 32 octets (e.g. notes.save)
```

**16 roles:** window, label, button, check, entry, **password**, list,
table, tab, menubar, choice, separator, scrollbar, menu, dialog, slider.
**7 state bits:** enabled, focusable, focused, selected, hidden, checked,
**protected**.

The name comes from the visible text; a list's name is empty and its value
is the selected row. An entry's name is its text (it is on the screen
anyway). `ax_name` overrides it. Place is window-relative; the window node
carries the window size.

**The bus action id.** `wlib.ax_action(button, "notes.save")` puts the
action into the node; `a11y.tree` exports it (`"Save" act=notes.save`),
and `a11y.press action=notes.save` finds the button by it. An agent can
see that clicking "Save" and calling `notes.save` are the same thing — and
call the action instead of the click.

## 3. The security decision — plainly

The tree carries everything on the screen: every label, list row, field
text, window title, and — through the events — where the user types. A
program that may read it is a reader of the screen. That is its job; so
it gets the right only explicitly.

### 3.1 Five rules

1. **Reading needs the kernel right `P_READ`, pressing `P_ACT`.** Both per
   task, both given only by euid 0 (`AX_PERM`). Without: `-EPERM` for
   every node, every event, every press, counted (`AI_DENIED`).
   *Measured:* `a11ydemo forge` without a right gets EPERM three times.
2. **The rights fall at exec** (`ax.drop_perm` in `ldr/elf.fi`, which
   every spawn passes, and in `sys.do_execve`, which replaces the image in
   place and does not). A reader that runs a shell does not hand
   it the screen. *Measured:* root grants itself both rights (mine=3),
   execs, and the new program has mine=0. This closes the first open point
   of the old branch. **Contrast with the bus label (AB-003):** the
   ORIGIN label is *sticky* across exec on purpose (it narrows who a
   program may claim to be); the tree right is *dropped* at exec on
   purpose (it widens what a program may see). Narrowing sticks,
   widening falls.
3. **Push only for oneself and one's own windows.** The kernel stamps the
   task into every node. A window node names its window-server id; the
   kernel maps it only if the caller owns that window, and every node of
   an unmapped window is refused (`AI_FOREIGN`). *Measured:* a forged push
   for a foreign window: 0 of 3 taken, 3 counted.
4. **Setting is root's.** `AX_SET` (contrast, magnifier, sticky keys,
   recording on/off) needs euid 0 — they hold for every window.
   `AX_INFO` is open: numbers *about* the tree, nothing *from* it.
5. **A press has a target rule** (`sysgui.ax_press`), besides `P_ACT`:
   only a button or check box that is enabled, visible and not protected;
   only if the tree did not change since it was read (generation); only
   into the window it was pushed for, owned by the pushing task; never
   while the screen is locked, never the desktop/panels/terminal, never
   the caller's own window; and **only a window of an app or a foreign
   program** (label `app:` or `compat:`). The user's own tools (settings,
   explorer, login, lock screen — no label) are never pressed: the
   settings window shows the "Yes, change it" of a critical bus call, and
   an agent with a press grant must not answer its own question. The press
   arrives in the app as window event `E_AXPRESS` and wlib handles it like
   a click. *Measured:* a disabled button (reason 2) and a user's own
   window (reason 7) are refused with EACCES.

### 3.2 The password field — two locks, and not even the length

A password field reports its role, place, size, state and the name the
program set — nothing else, **not its length**.

* **Ring 3** (`wlib.ax_build`): an entry with `F_PASSWORT` or `F_GEHEIM`
  becomes role `password` with value 0; its buffer is never copied into
  the name.
* **Kernel** (`ax.push_node`): a password node that arrives WITH a value
  gets value 0 — when it is **entered**, not when it is read — and the
  attempt is counted (`AI_LEAKS`).
* **axd** never prints a value for a protected node.

**The canary test.** The password field of a11ydemo holds `GEHEIMNIS7`.
The app prints only its length and a checksum. The runner then looks for
the word — and for the part `HEIMNIS` — in the whole serial line: every
tree export over the bus, the audit log, the kernel's own dump of the
store (`AX_SET 99`). Result: **0 occurrences.** A forged password node
with the canary's bytes as value is taken with value 0 and counted as one
leak attempt; wlib's own pushes counted none.

### 3.3 What this does *not* do

* A reader with `P_READ` sees **everything**, every window. There is no
  per-window or per-purpose right in the kernel; the bus grant is per
  action (`a11y.tree`, `a11y.find`, `a11y.press`), not per window.
* The press target rule trusts the ORIGIN label; an app can press
  buttons of *another* app once it has the grant. That is what a grant is.
* The window server is in the kernel; a bug in `ax.fi` is a kernel bug.

## 4. S-008: using the machine

### 4.1 Sticky keys

`a11ysticky` or `AX_SET(C_STICKY, 1)`. A modifier (Shift, Ctrl, Alt)
pressed and released **alone** latches for exactly the next key
(`kernel/drv/hid/kbd.fi`, `on_code` is a wrapper so the latch falls after
every one of its return points). "Alone" is `KB_SEEN`: without it every
ordinary Shift+A would drag a second capital behind it. It sits in the
keyboard, not in wlib, so it works in the shell as well.
*Measured:* Shift alone → `kbd: sticky latch=1`, the next Tab goes
backwards.

### 4.2 Magnifier — follows the focus

`a11ymag` or `AX_SET(C_MAG, 1)`. A cut-out, twice enlarged, in a panel of
200 × 150 at the top right (`wm.paint_mag`), painted after the pointer
from the finished picture. It follows **the focus or the pointer,
whichever moved last**: the focus is the focused node of the focused
window, from the tree, in screen coordinates — so a keyboard user sees
the control Tab just reached. If the cut-out would reach into the panel,
the panel moves to the top left (otherwise it would magnify itself).
The kernel says where panel and cut-out are (`ax: mag px= sx= sy= cx= cy=
mode=`); the runner checks **every panel pixel against its source pixel
in the screenshot** — not similarity, the same pixel.

### 4.3 High contrast

`a11yhigh` or `AX_SET(C_HIGH, 1)`. The scheme existed
(`assets/schemes/contrast.scheme`); the system-wide switch in front of it
is new. **Accessibility beats every other colour source:** wlibc takes the
contrast scheme whatever `/etc/theme.conf` says (also at night, the dark
scheme is ignored), skips the old override file `/etc/theme` (measured in
the old branch: it gave black text on dark ground, 1.3:1) and ignores a
program's own colour file. Switched at run time, every program picks it up
on its next theme poll. *Measured:* the WCAG ratio a program gets
(`a11ydemo theme`).

## 5. The calls

| Nr | Name | Arguments | who |
|---:|---|---|---|
| 1910 | `AX_PUSH` | begin (0,1) · nodes (ptr, n ≤ 32) · end (0,0) | anyone, only for itself |
| 1911 | `AX_READ` | (nr, dst, len) | `P_READ` |
| 1912 | `AX_EVENT` | (dst, len) | `P_READ` |
| 1913 | `AX_PERM` | (op, task, bits); task 0xFFFF = self | ask: anyone · grant/revoke: euid 0 |
| 1914 | `AX_INFO` | (field) | anyone (numbers only) |
| 1915 | `AX_SET` | (field, value); field 99 = dump the store to the serial line | euid 0 |
| 1916 | `AX_PRESS` | (nr, generation) | `P_ACT` + target rule |

The old branch had 1960..1965 — today `SYS_OSUM_BUS`; 1980..1985 are
AIO. `tools/kernel/syscalls.py --zweige` showed 1904..1949 free on every
branch. Everything goes through the seam `gfx.sys_ax`; a kernel built
with `--gui off` answers `-ENOSYS` (no windows, no tree).

**Memory:** `kstate.AX_OFF` 0x13E000..0x144000, the six pages the wave of
18.09.2026 allotted to this branch (the old 0x7A000 is NETDEV today).
224 nodes, 64 events, one rights word per task. The store is filled only
while recording is on (`a11y` on the command line, or axd); otherwise
wlib sends nothing and the layer costs one `AX_INFO` per 64 frames.

**Events:** focus change, value change (incl. checked/selected), rebuild.
When the ring overflows the oldest falls and `AI_EVDROP` counts it.

## 6. On the action bus (AB-021)

Reading and pressing the tree of *other* programs goes through the bus,
not through a side door: the provider `axd` (`/bin/axd`, manifest
`etc/actions.d/a11y.actions`, app `a11y`) runs as root, grants itself
`P_READ | P_ACT`, switches recording on and serves:

| action | level | what |
|---|---|---|
| `a11y.tree [window=] [from=]` | **write** | every node, one line each |
| `a11y.find [role=] [name=] [window=]` | **write** | the matching nodes |
| `a11y.press name=\| action= [window=]` | write | press exactly one enabled button/check box |
| `a11y.status` | read | numbers only (nodes, reads, denied, leaks …) |

**Why the reads are declared `write`:** the bus lets every client *read*
without asking (ACTION-BUS.md 5.1). The tree is the screen, so a read
level would hand it to any app. On the write level the user reads
freely; an app, Jarvis or a script needs a grant
(`allow jarvis a11y.tree write`, or `act grant jarvis a11y.* write 3600`)
or is asked, and Jarvis must dry-run first (`dryfirst jarvis`). A rights
name like "a11y.read / a11y.act" is simply the glob: `a11y.tree` +
`a11y.find` = reading, `a11y.press` = acting. No action says `dryrun`: the
broker answers dry runs itself (decision, level), so a dry run of
`a11y.tree` is never a way to read the screen.

*Measured:* Jarvis without dry run → `err dry_run_first`; dry run →
`decision=ask`; real read → parked for the human; after
`act grant jarvis a11y.tree write 60` → the tree. The user presses
"Save", "Add note" by its action id `notes.add`, the check box; the app's
own log shows the clicks. "Save" in two windows → `err ambiguous`.
Jarvis' press is asked and done after the human's yes. The audit log has
every read and press.

**With the trusted dialog (AB-004, ACTION-BUS-5).** A parked `a11y.tree`,
`a11y.find` or `a11y.press` of an agent is also put to the person in the
window server's own dialog; `act reject last` / `act confirm last` on the
shell takes it down again (measured: `wm: trusted dialog up/down`). While
it is up it takes every *real* key -- so a forgotten parked read would
also swallow sticky-key presses; the test rejects it first. The dialog
has no nodes in the tree and no window ring, so `a11y.press` can never
answer it: an agent cannot say yes to itself through the tree.

Listing format (fits the broker's 2047-octet reply; what does not fit says
`more_from=`):

```
node.5=button win700 12,156 100x28 enabled,focusable "Save" act=notes.save
node.3=password win700 12,72 396x24 enabled,focusable,protected "Password"
```

`win700` = task 7, ring-3 window 0.

## 7. What is still missing

1. **Text with structure** (caret, selection, lines) — the name is one
   line of 40 octets.
2. **Label relations** (`labelled_by`) and **live regions**.
3. **Language per node** for a speech output; the **speech output**
   itself, **Braille**.
4. **The terminal is not in the tree.**
5. **Events on the bus:** axd does not yet republish focus/value events
   as bus events (`a11y.changed`).
6. **Per-window rights** — see 3.3.
7. **Scaling** (`a11yscale` of the old branch) is not ported: wlib has its
   own UI scale since then (`wlibc.ui_scale`), the settings key
   `display.scale` covers it.
8. A settings page for the three S-008 switches (today: command line or
   `AX_SET` as root).
