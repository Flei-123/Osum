# WLAN-8265 -- Intel Dual Band AC 8265 (family 8000, PCI 8086:24fd) in the HP EliteBook x360 1030 G2

Status 23.10.2026. Companion of `docs/PLAN-8000-LOADER.md` (loader facts) and `docs/PLAN-LAPTOP-WLAN.md`.
Linux iwlwifi was read as a specification only (GPL); nothing is copied.

## 1. What exists and what was MEASURED (all on a model, no 8265 silicon was available)
- `lib/wlan/iwl_fh8000.fi`: FH chunk loader. Gate `tools/wlan/fh8000.sh` (69 checks incl. 20 mutants + pins): library vs. flow-handler model vs. independent Python reference.
- NEW: the REAL linux-firmware files `iwlwifi-8265-36.ucode` (2,432,528 B) pass through the same loader: Firn TLV parser == Python walk (ver 36, RT image 4 CPU1 + 4 CPU2 sections, 2 paging sections, 636,520 octets loaded in 10 chunks, 1 extended-range chunk), model trace == Python reference. Needs `WLAN_8265_FW=<file>`; skipped otherwise.
- NEW: kernel glue (`kernel/drv/net/iwl.fi`) logs `iwl: fw sha256=<hex> pin=<family>/<api>` using `lib/wlan/iwl_pin.fi`. Gate `tools/iwlfh/run.sh` (31 ok, 0 fail, QEMU/KVM): the real file is read through the VFS, hashed, recognised as pinned, parsed, loaded into a fake CSR/SRAM window (now 8 address windows, so the real addresses 0x0, 0x404000, 0x800000, 0x80457000, 0xC0080000... fit); a copy with ONE flipped octet is NOT recognised and gives another SRAM digest.
- Pins (SHA-256, files NEVER committed): 8265-36 `1336afcd...56`, 8265-34 `85566f94...f7`, 8000C-36 `47993172...7a`, 8000C-34 `5476ec3e...49ce` (full values in `lib/wlan/iwl_pin.fi`). Path on the target: `/lib/firmware/intel/iwlwifi/<name>`. A pin mismatch is only logged: Intel's boot ROM verifies the firmware signature itself.
- Failure paths (QEMU-gated): file missing -> `iwl: fw missing <path>` per candidate + `iwl: fw no file`, no register write; corrupt blob -> negative parse rc, no loader; lost end-of-TFD interrupt -> `RC -45` after the bounded poll (no hang); no ALIVE -> `iwl: boot rc=-<n>` and interrupts disabled. USB networking is untouched and stays the fallback.

## 2. NEW FINDING: family 8000 boots TWO images, the glue loads only one
Read in `mvm/fw.c` (`iwl_run_init_mvm_ucode`, `iwl_mvm_has_unified_ucode` is true only for family >= 22000): for the 8265 the driver first starts the INIT image, reads the NVM (MAC address, channels, regulatory) with `NVM_ACCESS_CMD`, sends TX-antenna + PHY config, waits for `INIT_COMPLETE_NOTIF`, stops the device and only then loads the REGULAR (RT) image. `kernel/drv/net/iwl.fi fh8000_boot` loads only IMG_RT -> that is NOT the full sequence. Real blob has both images (INIT image: 5 CPU1 + 4 CPU2 + 2 paging sections, from the Python walk).
Missing before scan/assoc is possible (all unmeasured, needs the HP):
1. RX ring + TX/command queue (legacy 128-octet TFD codec exists in `iwl_ctxt.fi`; RX RBD ring, `FH_RSCSR_*`, scheduler `SCD_*` and `FH_MEM_CBBC` setup do not).
2. INIT run: ALIVE notification parse, `NVM_ACCESS_CMD` section 10, PHY/antenna config, `INIT_COMPLETE`, device stop, RT load.
3. RT run: MAC/PHY/binding contexts, `ADD_STA`, scan request, TX_CMD framing, key install. Everything above the seam (`lib/wlan/device.fi`: scan, connect, WPA2 4-way, CCMP, DHCP) is already proven against the test device.

## 3. Licence of the firmware (Intel `LICENCE.iwlwifi_firmware`)
- `WHENCE` (linux-firmware, main) lists `iwlwifi-8265-34/36.ucode` and `iwlwifi-8000C-34/36.ucode` under: "Licence: Redistributable. See LICENCE.iwlwifi_firmware for details".
- Text read (2006-2015 Intel copy from a mirror; the current upstream path could not be fetched on 23.10.2026 -- re-check before shipping): redistribution and use in BINARY form WITHOUT modification is permitted if (a) the copyright notice, the conditions and the disclaimer are reproduced in the documentation/materials provided with the distribution, (b) Intel's name is not used to endorse products, (c) NO reverse engineering, decompilation or disassembly. Limited patent licence only together with an OSI-approved open-source OS; no hardware licensed. Disclaimer "AS IS".
- Consequences for OrientOS: bundling the unmodified file with the licence text is allowed by the text; the OS must ship the licence text next to it; the loader must never rewrite the blob (it does not -- read-only, only parsed); do not disassemble it. No lawyer review done -> Boss decision (project need filed).

## 5. Status 23.10. late (W-WLAN2): what is built, what is not
- HP-9c.2 DONE (sim): `kernel/drv/net/iwl.fi fh8000_phases` = power up -> INIT image -> ALIVE -> [NVM/calibration exchange: PENDING, needs HP-9c.1] -> stop (`stop_master` + `sw_reset`) -> power up -> RT image -> ALIVE. Lines `iwl: boot2 <phase> rc=<n>` on serial; every wait bounded; any failure disables interrupts and returns the rc (nothing hangs, USB networking stays). The fake models the CPU release (FH_UCODE_LOAD_STATUS all ones) -> ALIVE after 3 reads, counts ALIVEs/octets per phase, flags an RT load without a device stop as a violation. Gate `tools/iwlfh/run.sh` cases I2-I4 + real-blob checks (needs `WLAN_8265_FW`).
- HP-9c.3 PARTIAL: `lib/wlan/iwl_mvm.fi` encodes NVM_ACCESS_CMD, PHY_CONFIGURATION_CMD, TX_ANT_CONFIGURATION_CMD, PHY_CONTEXT_CMD (v1), ADD_STA (v7), ADD_STA_KEY (CCMP) and parses ALIVE/INIT_COMPLETE/NVM response headers. Gate `tools/wlan/mvm.sh` (7 commands byte-equal to a struct.pack reference + 3 mutants). Layouts from READING the Linux uapi headers; firmware API versions depend on the blob TLVs (not checked). NOT built: MAC_CONTEXT_CMD, BINDING_CONTEXT_CMD, SCAN (UMAC), TX_CMD framing.
- HP-9c.1 (RX/TX rings, scheduler) NOT built. Spec read: `FH_RSCSR_CHNL0_*` 0x1BC0.., `FH_MEM_RCSR_CHNL0_CONFIG_REG` 0x1C00, `FH_KW_MEM_ADDR_REG` 0x197C, `FH_MEM_CBBC_0_15` 0x19D0.., `SCD_BASE` PRPH 0xA02C00 (`SCD_DRAM_BASE_ADDR` +0x8, `SCD_TXFACT` +0x10). Command queue codec (`iwl_ctxt.fi` Txq) exists.
- Hence scan / WPA2 / DHCP on the 8265 do NOT run yet; the layers above the seam are proven against the test device only.

## 6. Firmware on the Boss stick (private) and Wi-Fi credentials
- `tools/usbimg/build.sh` copies `iwlwifi-8265-36.ucode` unmodified to `/lib/firmware/intel/iwlwifi/` (plus `LICENCE.iwlwifi_firmware`) when `WLAN_FW_FILE` (default `/root/fw-cache/iwlwifi-8265-36.ucode`) exists AND matches the SHA-256 pin `1336afcd...56`; never with `IMAGE_PROFILE=public`. Licence for a PUBLIC release must be re-checked first (the cached licence text is a 2006-2015 mirror copy).
- Credentials: `/etc/wlan.conf` with two lines `ssid <name>` and `psk <password>` (written by the terminal command `wlan verbinden <ssid> <psk>`, mode 0600) -- or at image build time with `WLAN_CONF=<file>`. The kernel does not read it yet (needs the connect path).
