# Consent dialogs: inventory and unification

## Before (what the Boss saw)
| Place | Mechanism | Look |
|---|---|---|
| Start Taskmanager / Store / Installer / diskctl / drvctl (`ulib.needs_root`) | `/bin/elevate` own fUi window, kernel `execas: priv` | window "Administrator rights needed", Allow/Cancel, mouse+Tab |
| Install/update/remove in Store (`store.*`) | action bus, level critical, parked token -> window server dialog `WM_TRUST` (compositor-drawn, real keyboard/mouse only) | "<product> - Confirmation (from the system)", J/N |
| Settings critical keys, `settings.update.*` | same bus + `WM_TRUST` | same |
| App rights (`net`, `fs.home`, ...) | kernel label `app:<name>` + grant table (apprights), changed from Settings via bus | no dialog of its own |
| Disk write unlock (`wunlock`, `diskact`) | typed confirmation (CLI / fUi entry) | intentionally different (destructive) |
| Device pairing (tray) | tray popup | local pairing, not privilege |
| `busy.alert/confirm`, explorer delete | in-window fUi modal | app-local questions |

Difference: elevate was a normal window of a root helper (can be covered, is clickable by synthetic input); the bus dialog is drawn by the compositor above everything and answers only on real input.

## Now
- One trust dialog: `kernel/ui/wm/wmtrust.fi`, drawn by the window server above all windows. `/bin/elevate` has no window of its own; it asks through `kernel/user/consent.fi` -> `WM_TRUST` like every bus confirmation.
- Look: accent band with shield, raised card panel, TTF text with umlauts (bitmap fallback), primary button "Allow", secondary "Cancel", focus ring, "More details" expander. Colours come only from palette roles (`kernel/ui/wm/wmrole.fi`, generated by `tools/palette/gen.py`).
- Title: "<product> - Do you want to allow this?" / "<Produkt> - Möchtest du das zulassen?". Buttons Allow/Cancel (message: OK/Close, question: Yes/No). Hint: real keyboard/mouse only, J/Y = allow, N = cancel, D = details.
- Injected input is refused: `tip.mark` stamps every `jarvisctl input` injection (key, scancode, move, button, OSK); `tip.injected_within` makes the dialog drop keys and clicks for 1.5 s after one and log `wm: trusted dialog refused injected input`. Gate `tools/trustdlg/run.sh` (counter-proof: kernel before the guard answers by injection).
- Text builder `kernel/user/trusttext.fi` has two registries: `META` (action pattern -> rights, publisher/signature phrase) and `RIGHTS` (id -> de/en text); action `system.elevate`.
- Programmes that need root (`ulib.needs_root`): settings page tools, installer, diskctl, drvctl. The Task Manager runs as the session user (read-only for other users' processes; the kernel `kill_allowed` check refuses foreign kills).
- Serial markers of elevate kept: `elevate: ready|allowed|denied|start`.
- Orphan locale keys `elevate.*` removed.

## Not done yet
- Password/PIN field for admin consent (the compositor dialog has no text field).
- Dim backdrop (secure desktop look; too costly per frame).
- The injection guard also blocks real input for 1.5 s after remote control; during continuous remote control use the emergency stop (Win+Esc) first.
- Generic dialog API: done, see docs/ui/dialog-api.md (dialog.fi, menu.fi, /bin/msgbox, gate tools/dialog).
- Store opens as the session user (no elevate); the privileged work runs in the store daemon, so install/update/remove ask exactly ONCE through the bus dialog.
- Dialog scale follows `uiscale` (reduced step by step until the 68-column panel fits the screen); every title starts with the product name.
