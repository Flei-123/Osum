# Debug over the network (dbgsrv)

Read-only HTTP service for the HP without photos: `/bin/dbgsrv`, port 8765, started by init (`netz`, respawn), log `/var/log/dbgsrv.log`.

## Rules
- Only local peers: 10/8, 172.16/12, 192.168/16, 169.254/16, 127/8. Any other peer is dropped without an answer (`dbgsrv: refused non-local`).
- Token required: file `/etc/dbgsrv.token`. Missing or empty token file = service refuses to start.
- GET only. No write, no exec from the client side. The path list is fixed (`lib/dbgsrv/routes.fi`, generated by `tools/dbgsrv/genroutes.py` from `routes.fi.in`).

## Token
- `tools/usbimg/build.sh` (personal profile, `DBGSRV=0` switches off, `DBGSRV=1` forces on) writes a random token next to the image: `<image>.dbgsrv.token` (mode 600) and puts it into the image as `/etc/dbgsrv.token`.

## Use from the laptop (same LAN as the HP)
- IP: the HP shows it in the network view; `/run/dbgsrv.url` holds `http://<ip>:8765/`; the console line is `dbgsrv: address is ...`.
- `curl -H "X-Token: $(cat orientos-usb-hp-XYZ.dbgsrv.token)" http://<ip>:8765/wlan`
- Also accepted: `Authorization: Bearer <token>` or `?t=<token>`.

## Endpoints
`/` list, `/wlan`, `/drivers`, `/net`, `/pci`, `/usb`, `/lspci`, `/lspci/v`, `/dmesg` (log -n 400), `/klog`, `/svclog` (jarvisd log), `/dbgsrvlog`, `/wlanctl/status`, `/wlanctl/dump`, `/version`, `/uptime`.

## Gates
- `bash tools/dbgsrv/run.sh` (host: ACL, token parser, routes, generator in sync)
- `heavy bash tools/dbgsrv/qemu.sh` (QEMU: DHCP over usb-net, 401/200/404/405, public peer dropped via `-X`, tokenless instance, token not in log)
- `heavy bash tools/usbnet/qemu.sh` (DHCP + ping over usb-net ECM)

## Not verified
- CH336 on real silicon (no QEMU model); the generic stack above runs over CDC-ECM.
- Showing the IP in the login screen is not done; use the network view.
