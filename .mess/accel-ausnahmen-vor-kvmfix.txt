# Ein Eintrag hier heisst: dieser Abschnitt laeuft auf TCG, OBWOHL /dev/kvm
# da ist. Das kostet Zeit, also braucht jeder Eintrag einen GEMESSENEN
# Grund -- nicht eine Vermutung. Wer einen Eintrag entfernt, muss den
# Abschnitt vorher unter KVM gruen gemessen haben.
#
# NICHT hier stehen die drei, die von vornherein nicht umgestellt wurden;
# sie setzen ihr `-accel` selbst im Quelltext bzw. sind ein anderer Bogen:
#   tools/hv/run.sh    -accel tcg, misst dass TCG kein VT-x kann
#   tools/smp/run.sh   -accel tcg,thread=single|multi, misst genau das
#   tools/arm/run.sh   qemu-system-aarch64, KVM auf x86 unmoeglich
#
# Zum Messen laesst sich diese Liste mit OSUM_ACCEL_FORCE=1 abschalten,
# und OSUM_ACCEL=tcg|kvm schlaegt sie ohnehin.
#

# EINTRAEGE
# GEMESSEN am 28.08.2026 auf diesem Wirt (AMD EPYC, /dev/kvm 0666), je ein
# voller serieller Lauf unter OSUM_ACCEL=tcg und OSUM_ACCEL=kvm. Alle hier
# gelisteten Abschnitte waren unter KVM ROT und unter TCG (bis auf die drei
# mit dem Vermerk VORSCHADEN) gruen. Das Muster ist in JEDEM Fall dasselbe:
# der Kernel bleibt an einer Ausnahme stehen, QEMU endet mit exit code 63.
#
# Belegt sind zwei Ursachen (Register in .mess/diag-kvm-*.txt):
#   * #GP mit rcx=0x1a2 -- rdmsr auf IA32_TEMPERATURE_TARGET, ein MSR, das
#     es nur auf Intel gibt; unter TCG antwortet QEMU brav, echte AMD-
#     Hardware unter KVM wirft #GP.
#   * ein Selektorfehler im sysret-Rueckweg nach Ring 3.
# BEIDE werden von der parallel laufenden Runde `kvmfix` im Kernel behoben.
# Diese Runde fasst kernel/ nicht an. Nach dem Zusammenfuehren von kvmfix
# gehoert jede Zeile hier EINZELN unter KVM nachgemessen und bei Gruen
# gestrichen -- dann erst zahlt sich der KVM-Hebel aus.
